# الخطوة 1ب: البحث على الويب — أداة مدمجة مقابل استدعاء الدوال (Tavily)

> **دروس الكورس المطبّقة:** 4.2 استدعاء الدوال (Function Calling) · 4.3 الأدوات المدمجة · وتطبيق جديد للدرس 5.1 (معالجة الأخطاء)

## ماذا سنبني في هذه الخطوة؟

في الخطوة 1 رأينا أن محلل الشركة يعطي `competitors: []`، لأن مواقع الشركات لا تذكر منافسيها. الحل هو البحث على الويب، لكن الأداة المدمجة `web_search` غير متاحة على Azure.

في هذه الخطوة نبني **أداة بحث خاصة بنا** عبر خدمة Tavily، ونعطيها للنموذج بـ **استدعاء الدوال**. النتيجة أن الخيار `--web` يعمل الآن على Azure وعلى OpenAI معاً، مع حقل جديد في الملف `sources` يذكر روابط المصادر التي استُخدمت.

ثلاث طرق لتشغيل المحلل بعد هذه الخطوة:

| الأمر | ماذا يحدث | يعمل على Azure؟ |
| --- | --- | --- |
| `--web tavily` | النموذج يطلب البحث، **كودنا** ينفّذه عبر Tavily | نعم |
| `--web openai` | **خوادم OpenAI** تبحث بنفسها (الأداة المدمجة) | لا |
| `--web` وحده | يختار Tavily إن وُجد مفتاحه، وإلا الأداة المدمجة | نعم، إن وُجد مفتاح Tavily |

1. سجّل في `https://app.tavily.com` (بحساب Google أو بريدك).

الخطة المجانية تعطي رصيداً شهرياً من "الأرصدة" (credits)؛ كل بحث `basic` يستهلك رصيداً واحداً. راجع لوحة Tavily لمعرفة رصيدك الحالي.

```powershell
git checkout main
git pull
python -m scripts.check_env
```

يجب أن ترى سطراً مثل: `Tavily key : tvly-*** (NN chars) ok`.



## المفاهيم: ماذا تعلّمنا من الكورس هنا؟

### الأداة المدمجة مقابل الدالة: من ينفّذ؟ (الدرسان 4.2 و 4.3)

هذا أهم مفهوم في الخطوة. في الحالتين النموذج هو الذي **يقرر** أن يبحث وماذا يبحث. الفرق في **من ينفّذ**:

| | الأداة المدمجة `web_search` (4.3) | الدالة `search_web` (4.2) |
| --- | --- | --- |
| من ينفّذ البحث | خوادم OpenAI | كودنا على جهازك |
| عدد الاستدعاءات للنموذج | استدعاء واحد | استدعاءان أو أكثر (حلقة) |
| كود نكتبه | سطر واحد | الوصف + الدالة + الحلقة |
| يعمل على Azure | لا | نعم |
| مصدر البحث | تختاره OpenAI | نحن نختاره (Tavily هنا) |
| التحكم | قليل | كامل: نقص النتائج، نسجّلها، نعالج أخطاءها |

### كيف يعمل استدعاء الدوال؟ (الدرس 4.2)

النموذج **لا يستطيع تشغيل أي كود**. كل ما يفعله أنه يكتب رداً خاصاً معناه: "أريد تشغيل الدالة `search_web` بهذه المعاملات". كودنا يقرأ هذا الرد، وينفّذ الدالة، ثم يعيد النتيجة للنموذج في استدعاء جديد.

مسار المحادثة الكامل لتحليل واحد:

| الدورة | نحن نرسل | النموذج يرد |
| --- | --- | --- |
| 1 | نص الموقع + وصف الأداة | `function_call`: ابحث عن `"Lucidya competitors"` |
| — | (كودنا يبحث في Tavily) | — |
| 2 | كل ما سبق + طلبه + نتائج البحث | `function_call`: ابحث عن `"Lucidya social listening platform"` |
| — | (كودنا يبحث مرة أخرى) | — |
| 3 | كل ما سبق + النتائج الجديدة | `CompanyProfile` النهائي بصيغة JSON |

لاحظ أن **كل دورة تعيد إرسال كل ما قبلها**. الـ API لا يتذكر الدورة السابقة من تلقاء نفسه (في وضعنا هذا)، فنحن نحمل "التاريخ" في القائمة `items`. هذا يعني أن رموز الإدخال تزيد في كل دورة، ولهذا وضعنا حداً للدورات.

### 1) وصف الأداة: ما يراه النموذج

النموذج لا يرى كود Python أبداً. يرى فقط هذا الوصف بصيغة JSON Schema:

```python
SEARCH_TOOL = {
    "type": "function",
    "name": "search_web",
    "description": (
        "Search the web for facts that are not on the company website, "
        "such as competitors or what others say about the company."
    ),
    "parameters": {
        "type": "object",
        "properties": {
            "query": {"type": "string", "description": "Search query, 2-8 words, e.g. 'Lucidya competitors'"}
        },
        "required": ["query"],
        "additionalProperties": False,
    },
    "strict": True,
}
```

| الحقل | دوره |
| --- | --- |
| `name` | الاسم الذي سيذكره النموذج في طلبه |
| `description` | **متى** يستخدم الأداة. هذا نص تعليمات فعلي؛ اكتبه بعناية |
| `parameters` | شكل المعاملات بصيغة JSON Schema، مثل مخطط المخرجات المهيكلة في الخطوة 1 |
| `strict: True` | يُجبر النموذج على معاملات مطابقة للمخطط تماماً، فلا نتلقى `{"q": ...}` بدل `{"query": ...}` |

وصف المعامل فيه **مثال** (`'Lucidya competitors'`) لأن الأمثلة توجّه النموذج لكتابة استعلامات قصيرة وفعالة، بدل جمل طويلة.

### 2) الدالة الحقيقية: `core/search.py`

طلب واحد إلى Tavily:

```python
resp = http.post(
    TAVILY_URL,
    headers={"Authorization": f"Bearer {key}"},
    json={
        "query": query,
        "max_results": max_results,
        "search_depth": "basic",  # 1 credit per search ("advanced" = 2)
        "topic": "general",
    },
    timeout=timeout,
)
```

- **المفتاح في الترويسة (header)** وليس في جسم الطلب. هذا هو الأسلوب الذي توصي به Tavily، ويشبه ما يفعله OpenAI SDK مع مفتاحك.
- **`basic`**: رصيد واحد لكل بحث. `advanced` أدق لكنه برصيدين.
- **`timeout=20`**: لا ننتظر للأبد إذا تأخرت الخدمة.

ثم نقص كل نتيجة عند 700 حرف:

```python
MAX_CONTENT_CHARS = 700
```

خمس نتائج × 700 حرف ≈ 1,000 رمز لكل بحث. بدون هذا القص قد ترسل Tavily نصوصاً طويلة جداً، وكلها ستُحسب رموز إدخال في الدورة التالية، ثم في كل دورة بعدها. هذا نفس مبدأ `web.py`: **نظّف وقصّ قبل أن ترسل للنموذج.**

`format_results()` ترقّم النتائج وتضع الرابط تحت كل عنوان، فيسهل على النموذج أن ينقل الروابط الصحيحة إلى حقل `sources`.

### 3) الحلقة: `_run_search_loop()` في `agents/researcher.py`

```python
for round_no in range(MAX_SEARCH_ROUNDS + 1):
    last_round = round_no == MAX_SEARCH_ROUNDS
    response = ask(
        items,
        task="smart",
        instructions=instructions,
        text_format=CompanyProfile,
        tools=[SEARCH_TOOL],
        tool_choice="none" if last_round else "auto",
        client=client,
    )

    calls = [item for item in response.output if item.type == "function_call"]
    if not calls:
        return response, searches
```

- **`tool_choice="auto"`**: النموذج حرّ، يبحث أو يجيب.
- **`tool_choice="none"`** في الدورة الأخيرة: ممنوع البحث، فيُجبر على كتابة الملف. هذا **صمام أمان**: بدونه قد يستمر النموذج في البحث دورة بعد دورة، وكل دورة تكلّف أكثر من سابقتها.
- **`if not calls`**: إذا لم يطلب النموذج أي دالة، فرده هو الملف النهائي.

لاحظ أننا نمرر `tools` و `text_format` معاً. النموذج يختار في كل دورة: إما طلب دالة، وإما رد بصيغة `CompanyProfile`. المخرجات المهيكلة تبقى مضمونة في الرد النهائي.

لكل طلب من النموذج نضيف عنصرين إلى التاريخ:

```python
items.append(
    {
        "type": "function_call",
        "call_id": call.call_id,
        "name": call.name,
        "arguments": call.arguments,
    }
)
...
items.append({"type": "function_call_output", "call_id": call.call_id, "output": output})
```

- **العنصر الأول** هو طلب النموذج نفسه. نعيده لأن النموذج يحتاج أن "يتذكر" أنه طلب هذا البحث.
- **العنصر الثاني** هو النتيجة، ويحمل **نفس `call_id`**. قد يطلب النموذج بحثين في رد واحد، و`call_id` هو ما يربط كل نتيجة بطلبها.
- **لماذا نبني العنصر الأول يدوياً** بدل إضافة `response.output` كما هو؟ لأن `responses.parse` تضيف إلى كل عنصر حقولاً خاصة بالـ SDK (مثل `parsed_arguments`)، والـ API قد يرفض الطلب إذا أعدناها له. نرسل الحقول الأربعة المطلوبة فقط.

`call.arguments` نص JSON وليس قاموساً، لذلك نحوّله قبل القراءة:

```python
query = json.loads(call.arguments).get("query", "")
```

### 4) أخطاء الأداة تذهب للنموذج، لا تُسقط البرنامج (الدرس 5.1)

```python
try:
    results = search(query)
    output = format_results(query, results)
except Exception as err:  # tell the model instead of crashing
    results, output = [], f"Search failed: {type(err).__name__}: {err}"
```

لو تأخرت Tavily أو نفد رصيدها، لا نوقف التحليل كله. نخبر النموذج أن البحث فشل، فيكمل بما لديه من نص الموقع، ويضع غالباً `confidence` أقل. هذا نمط شائع مع الوكلاء: **الأداة الفاشلة معلومة مفيدة للنموذج، وليست سبباً لإيقاف كل شيء.**

### 5) اختيار الوضع: `resolve_web_mode()`

```python
if web == "auto":
    web = "tavily" if tavily_key() else "openai"
if web == "openai" and config.IS_AZURE:
    raise ValueError(...)
```

`auto` يفضّل Tavily لأنه يعمل مع أي مزوّد. وعلى Azure بدون مفتاح Tavily نفشل **قبل** أي استدعاء، برسالة تخبرك بالحل.

### الحقل الجديد `sources`

أضفنا إلى `CompanyProfile`:

```python
sources: list[str] = Field(
    description="URLs of web search results you actually used. Empty list if you did not search."

```

مع حقل `evidence` من الخطوة 1، صار عندنا تتبّع كامل: الاقتباسات تثبت ما جاء من الموقع، والروابط تثبت ما جاء من البحث. تستطيع فتح أي رابط والتأكد أن المنافس المذكور موجود فيه فعلاً.

## التكلفة

تحليل مع بحثين يعني ثلاث دورات للنموذج، وكل دورة تحمل ما قبلها:

| الدورة | رموز إدخال تقريبية | السبب |
| --- | --- | --- |
| 1 | ~6,000 (أو ~9,000 مع صورة) | نص الموقع + وصف الأداة |
| 2 | ~7,000 | + البحث الأول (~1,000) |
| 3 | ~8,000 | + البحث الثاني (~1,000) |
| **المجموع** | **~21,000** | تقريباً 3 أضعاف التحليل بدون بحث |

مع `gpt-4o-mini` هذا نحو **0.004 $** للنماذج، + رصيدان من Tavily. كل الدورات مسجّلة في `logs/calls.jsonl` بأرقامها الحقيقية؛ السكربت يطبع رموز **آخر** دورة فقط.

سنرى في الخطوة 3 (الدرس 2.4) كيف يخفّض **التخزين المؤقت للموجّهات** تكلفة الدورات المتكررة، لأن بدايتها متطابقة.

## أخطاء شائعة وحلولها

| ما تراه | السبب | الحل |
| --- | --- | --- |
| `ValueError: TAVILY_API_KEY is not set` | لم تضف المفتاح، أو ما زال `tvly-...` | ضع المفتاح الحقيقي في `.env`، وتحقق بـ `check_env` |
| `ValueError: ... not available on Azure OpenAI` | استخدمت `--web openai` أو `--web` بلا مفتاح Tavily | استخدم `--web tavily` بعد إضافة المفتاح |
| `[search] ... -> 0 results` ونص `Search failed: HTTPError` | مفتاح Tavily خاطئ (401) أو الرصيد انتهى (432/429) | تحقق من المفتاح والرصيد في لوحة Tavily |
| لا يظهر أي سطر `[search]` | النموذج قرر أن الموقع يكفي | طبيعي أحياناً؛ التعليمات تسمح له ألا يبحث |
| `BadRequestError` يذكر `tools` أو `function` | النشر على Azure لا يدعم استدعاء الدوال مع هذا الإصدار | استخدم `gpt-4o-mini` (2024-07-18) أو أحدث |
| `competitors` ما زالت فارغة مع وجود بحث | النتائج لم تذكر منافسين صراحة | هذا التزام صحيح بقاعدة "لا تخترع"؛ افتح `sources` وتحقق |
